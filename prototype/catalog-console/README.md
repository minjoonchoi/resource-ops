# resource-ops HTML 카탈로그 콘솔

`index.html` 하나에 CSS, JavaScript, 아이콘, React와 YAML 파서를 내장한 독립 실행 시뮬레이터입니다.
Sites 버전의 네 화면과 조작 기능을 HTML로 옮겼습니다. 실행에는 Node.js, 개발 서버, CDN, ChatGPT 로그인이 필요하지 않습니다.

## 열기

1. 이 디렉터리의 `index.html`을 내려받습니다. GitHub 파일 미리보기는 HTML을 실행하지 않습니다.
2. 내려받은 파일을 Chrome, Edge, Firefox, Safari 등 JavaScript를 지원하는 최신 브라우저로 엽니다.
3. 수집·동기화·롤백·체크리스트는 브라우저 저장소에 기록됩니다. 파일 URL의 저장·클립보드 지원은 브라우저 설정에 따라 다를 수 있습니다.
4. 우측 상단 초기화 버튼으로 예시 데이터로 돌아가거나, ‘이력 내보내기’로 JSON을 저장합니다.

`index.html` 외에 다른 파일을 함께 내려받을 필요는 없습니다. 근거 문서의 GitHub 링크는 직접 누를 때만 열립니다.
앱의 Content Security Policy는 외부 네트워크 요청을 차단합니다(`connect-src 'none'`).

## 데이터와 리비전

- 모든 원문·운영 SHA·시각·리비전은 예시입니다. 계약 비교의 ‘확인한 소스’ 커밋만 실제 조회 값입니다.
- 수집은 리비전을 생성하지 않습니다. 원문이 같으면 기존 스냅샷을 재사용하고 수집 관측 시각을 추가합니다.
- 원문이 바뀌면 동기화가 성공한 뒤에만 새 파일 리비전이 생기고 적용 포인터가 변경됩니다.
- 검증 오류와 동기화 실패는 적용 리비전을 유지합니다. 동일 원문 재시도와 드리프트 복구로 리비전을 중복 생성하지 않습니다.
- 최초 성공은 리소스 등록, 완전한 수집에서 확인한 파일 부재는 논리 삭제, 동일 ID의 재등장은 복원으로 표시합니다.
- 불완전한 트리 수집은 삭제 판정에 사용하지 않습니다. 이전 스냅샷과 이력은 보존합니다.
- 선택 롤백은 기존 리비전으로 적용 포인터를 전환하고 사유를 감사 이력에 기록합니다. 원문·Git은 바뀌지 않습니다.
- 적용 상태와 최신 원문이 다르면 드리프트입니다. 롤백 후 최신 원문 재적용은 기존 최신 리비전을 재사용합니다.

## 목표 키 규칙과 미확인 계약

Page/Task/Capability는 `platform/<platform_code>/<workspace_code>/<domain>/**.yaml` 경로와
`platform_code.workspace_code.domain.유형-*` 이름을 대조합니다.
Service는 `service/<organization_code>/**.yaml`, `*-api` 이름, `organization_code-*-api` 전역 키를 검사합니다.

서비스 정규화는 **콘솔 설계 가정**입니다. 경로의 조직 접두어가 이름에 없으면 붙이고, 같은 접두어가 있으면 유지합니다.
이 규칙의 실제 소비자 수용 여부와 이름 변경/참조 이관은 미확인입니다.
YAML 문법·경로·이름·전역 중복만 검증하며, 예시 spec의 실행 의미를 확정된 계약으로 취급하지 않습니다.

기존 resource-ops는 전체 snapshot의 단일 DB 트랜잭션과 Git revert PR 방식의 롤백을 명세합니다.
이 HTML은 요청한 **독립 파일 단위 부분 성공과 선택 리비전 롤백**을 시뮬레이션합니다.
Task/Capability 관계, 플러그인·요청/응답 규칙의 소유권, 외부 정책 참조에 따른 삭제 차단,
참조가 있는 리소스들의 원자성, Orion API·DB·Gateway 실행 호환성은 미확인으로 유지합니다.
운영 파서·생성기·DB 동기화 계약을 이 프로토타입에 맞춰 변경하지 않습니다.

근거는 resource-ops `36ce08baadde9e8d275d76fcded70140d4bf2553`,
Orion `966c449013273553c7912f74b4f02945c048396c`의 화면 내 링크를 참고합니다.

## 수정과 재생성

실행 파일은 `index.html`, 편집 원본은 `src/`입니다. HTML의 압축된 번들을 직접 수정하지 않습니다.
재생성에만 Node.js 24 이상이 필요합니다.

```sh
cd prototype/catalog-console
npm ci
npm run build
npm test
npm run check
```

`npm run check`는 소스에서 재생성한 HTML·라이선스 고지가 커밋된 파일과 같은지 검사합니다.
lockfile로 빌드 입력을 고정하며, 현재 빌드는 외부 런타임 자산을 사용하지 않는 약 455 KB HTML을 생성합니다.

## 검증 범위

15개 자동 검증: 원문 해시·Unicode·CRLF, 경로/유형/이름/중복, 동일 원문 수집, 수집과 동기화의 분리,
실패 보존·재시도, 삭제·복원, 롤백·재적용, 드리프트, 불완전 수집, 부분 실패, 최초 등록,
시나리오 반복 실행, 보안 컨텍스트 Crypto API가 없는 환경, 독립 HTML 구문·자산 내장·네트워크 제한.

생성된 HTML을 로컬 정적 서버에서 열어 수집·전체 동기화·파일별 리비전 조회를 브라우저로 확인했습니다.
직접 `file://` 열기는 자동 검증 브라우저의 정책상 확인하지 못했으며, Crypto API 미지원 경로는 자동 테스트로 검증했습니다.
[리비전 화면 검증 캡처](qa/revisions.jpg)를 함께 보관합니다.

운영 저장소 쓰기, 실제 DB/Gateway 동기화, Task/Capability 소비자 통합 검증은 수행하지 않습니다.
